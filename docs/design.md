# Design System

Urban Radio is a station tool, not a marketing toy. The UI should feel sharp, calm, and ready for a live room.

## Product Vibe

- Energetic, but not chaotic.
- Dense enough for operators who repeat workflows all day.
- High contrast where timing matters.
- Quiet surfaces around controls that need focus.
- Clear warnings before anything risky.

## Experience Principles

- The first screen is the workbench: broadcast console, queue, transport, carts, meters, and status.
- Operators should scan state in under one second.
- Destructive or show-impacting actions need visible state and guardrails.
- Low-resource mode should still look intentional, not broken.
- Text should be short, direct, and operational.

## Visual Direction

- Dark station-first UI with practical contrast.
- Neon accents only for live state, VU, warnings, and high-signal controls.
- Cards are for repeated items and control groups, not page decoration.
- Avoid nested cards.
- Use icons for fast tool recognition.
- Keep mobile usable, but optimize the main station workflow for desktop/wide screens.

## Core Screens

- Broadcast console: on-air command center.
- Queue: upcoming audio and timing confidence.
- Carts: instant-fire reliability.
- Scheduler: timed spots, breaks, and automation events.
- Settings: routing, input, crossfades, integrations, updates, appearance.

## States That Must Be Obvious

- On-air / stopped.
- Mic live / closed.
- Preview available / disabled.
- Scheduler pending / fired.
- Stream target valid / invalid.
- Update available / checking / blocked while on-air.
- Low-resource mode enabled.

## Copy Style

Use direct language:

- "Check for updates"
- "Install update"
- "Stop program audio before installing"
- "Stream key is required"
- "Preview disabled: no monitor output"

Avoid vague hype inside the app. Save energy for README/docs; keep the station UI operator-grade.
